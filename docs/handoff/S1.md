# S1 handoff: Lead search and Place ingestion

Branch `ws/leads`. Items 4, 5, 11, 12. `npm test` green (32 tests). Verified live with
`npm run leads:api -- "restorant" "Prishtinë" --pages 1` (twice: the rerun left every known `state.json` byte-identical).

## What landed

- `factory/lib/place.mjs`: `readPlace(slug)`, `writePlace(slug, place)` (auto-commits like `writeState`), `hasPlace(slug)`,
  `hasRealWebsite(url)`, `photoUrl(name, maxWidthPx = 1600, key = process.env.GOOGLE_PLACES_KEY)`.
- `factory/jobs/lead-search.mjs`: the search + filter logic from the old `leads/places-api.mjs`, as a job.
  `params: { query, city, pages = 3, types?: 'a,b' | [...], all?: boolean }`, no slug. Returns
  `{ found, kept, created, updated, dropped, cache }`. Registered in `factory/jobs/index.mjs` as `lead-search`.
- `leads/places-api.mjs`: argv → `runJob('lead-search', { params })`, prints the log, exit 1 on failure.
- `place.json` follows the contract: photos are `{ name, width, height, author: { name, uri } | null }` (all 10 when Google
  has 10), `review_snippets` are `{ text, author (first name only), rating }` (up to 5). Two fields beyond the contract:
  `vertical` is the vertical id (`restaurant`), and `query` keeps the search keyword (`restorant`). No URL with a key is
  written anywhere; `photoUrl()` reads the key at call time.
- `leads/out/<query>-<city>.json` is now a cache of the whole batch: every result in `place.json` shape, kept ones with
  `slug`, dropped ones with `dropped: "<reason>"`. No `status` field any more; status lives in `state.json`.

## Decisions beyond the brief

- `hasRealWebsite` also returns false for `wa.me`, `whatsapp.com` and `fb.com`. Google lists a WhatsApp booking link as
  the "website" of Smoke House Prishtina; that is a contact link, not a site, and exactly the funnel we would build.
- A known Place (`place.json` exists for the same `place_id`) gets its `place.json` rewritten on every search
  (`fetched_at`, rating, photos move on), `state.json` is never touched, not even `flags.hasRealWebsite`. If Google gains
  a real website for a Place later, the flag stays as it was at discovery; the Portal can flip it by hand.
- A folder with `state.json` but no `place.json` (`demo-restaurant` style fixtures) gets a `place.json` written and the
  existing state kept; the log says `existing state <status> kept`.
- 18 real Places from Prishtinë now sit in `places/` as `found` on this branch. They are
  real lead data, committed separately so the commit can be dropped if the operator would rather start clean.
  Google lists Princesha Gresa twice (`princesha-gresa-restaurant` from the migration and `restaurant-princesha-gresa`,
  a second place ID); decline one in the Portal.
- `places/la-tarte/place.json` still carries the migrated shape (6 photos, `author: null`). It was not in this page of
  results; `npm run leads:api -- "La Tarté" "Prishtinë" --pages 1` refreshes it (warns "no type list", keeps everything).

## For S3 (generation)

- Read `place.json` via `readPlace(slug)`. Photos are names: `photoUrl(photo.name, 1600)` on the way to a fetch.
  **Do not write the result of `photoUrl()` into `config.json`** or the key is back in git (item 11). Until S2's pool
  exists, either store the name in `config.json` and resolve it at build time, or let `build` copy the fetched files
  into `places/<slug>/photos/` and reference those. Attribution for item 17 is `photo.author`.
- `review_snippets` are objects now, not strings (`demo.mjs` line 36 stringifies them into the prompt, which still works
  but reads oddly; use `text` and `author`). `types`, `type`, `hours` are unchanged.
- `place.vertical` is the id, not the keyword: `guessVertical(lead)` in `demo.mjs` line 130 will keep working, but
  the real source is now `place.vertical`.
- The old `npm run demo -- leads/out/x.json <index>` path is broken by the cache's new photo shape (objects, not URLs)
  until `demo.mjs` reads `place.json`. `factory/batch.mjs` finds no `status: "new"` leads any more; the plan already turns
  it into `generate-all` over `found` Places with `flags.hasRealWebsite === false`.

## For S5 (Portal)

  `updated <name> -> <slug> (…)`, `dropped <name>: <reason>`, then a summary line ending in the cache path.
