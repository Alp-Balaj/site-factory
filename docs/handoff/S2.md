# S2 handoff: Photo pool

Branch `ws/photos`. Items 13, 14, 15, 16. `npm test` green (44 tests), `npm run build -- demo-restaurant` green.

## What landed

- `factory/jobs/photos.mjs`: one job, stages `discover → fetch → store → curate`, `--stage a,b` picks a subset,
  `--no-vision` uses the mechanical picks, `--rediscover` redoes a handle found by google/search (never a manual one),
  `--posts N` caps the Instagram posts (default 20). `photos.json` is written after every stage. Registered as `photos`.
- `factory/lib/photos/`: `google.mjs` (Places photos, `photoUrl`), `instagram.mjs` (handle discovery, Apify posts),
  `store.mjs` (sharp resize, R2 upload with size check), `curate.mjs` (vision call, fallback picks), `pool.mjs`
  (`photos.json` read/write, stable ids by ref). Fixture Place under `factory/lib/photos/fixtures/place.json`.
- `.env.example`: `APIFY_TOKEN`, `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET`, `R2_PUBLIC_URL`.
- `package.json`: `sharp`, `@aws-sdk/client-s3`.
- Real runs on this branch: `places/la-tarte/photos.json` (handle `latarteprishtina` found by Claude search, 6 Google
  photos, vision picks) and `places/liburnia/photos.json` (handle rejected, see below; vision picks with a landscape hero).

## For the integration session

1. **`photoUrl` is duplicated.** S1 had not merged, so `factory/lib/photos/google.mjs` carries its own two-line
   `photoUrl(name, width)`. Once `factory/lib/place.mjs` is on master, replace the local function with
   `import { photoUrl } from '../place.mjs'` (same signature) and delete the copy.
2. **Local store needs a copy step in `build.mjs`.** Without R2 the pool URLs are relative (`photos/g01-1600.webp`).
   When `photos.json` has `store: "local"` (or any config photo `src` starts with `photos/`), copy
   `places/<slug>/photos/` into `places/<slug>/build/photos/` after `astro build`. `factory/lib/paths.mjs` already
   exports `photosDir(slug)` and `buildDir(slug)`. Only the `-1600.webp` and `-800.webp` files are needed in the build;
   originals can stay out.
3. **Wiring:** `generate` should enqueue `photos` first when `photos.json` is missing (plan checklist). The job needs
   `place.json`; it throws a plain error without it. It never transitions status.
4. **S3 reads** `photos.json.picks.hero` / `picks.gallery` (ids) and resolves them through `pool[].web` for the site and
   `pool[].thumb` for the theme call; `pool[].scores` and `note` feed the theme prompt; `pool[].author` (Google only)
   and `pool[].source` feed the config photo objects for S6's attribution. Entries carry `caption` (Instagram) for the
   copy call. Ids are stable across reruns (`g01`, `i03` …): an entry keeps its id as long as its `ref` is the same.
5. **Handle matching is strict on purpose**, as the brief specified: profile name must slugify to the Place name, or
   confidence >= 0.8 with the city in the bio. Real near-miss: Liburnia's search returned `@restaurantliburnia`
   ("Restaurant Liburnia", 0.91, bio without the city) and was rejected. If that pattern repeats, a small loosening
   (strip a leading/trailing "restaurant"/"restorant"/"cafe" before comparing) belongs in `matchesPlace()` in
   `instagram.mjs`; the Portal's manual field is the fix today.
6. **Not verified against live services:** Apify and R2 (the operator had no token or bucket yet). The Apify call is
   unit-tested against the documented `run-sync-get-dataset-items` shape; the R2 path is tested end to end through the
   real `@aws-sdk/client-s3` client against an in-process mock S3 server (`R2_ENDPOINT` env, test-only). First live run:
   `node factory/jobs/run.mjs photos la-tarte --stage store` with the five `R2_*` lines filled, then once more to see
   "0 file(s) uploaded". For Apify: `--stage fetch,store,curate` with `APIFY_TOKEN` set; a failing actor run is a log
   line, not a failed job.
7. **Vision note goes into the theme note.** The prompt forbids emoji and dashes so S4's copy checks do not trip; the
   note is English, two or three sentences.
8. **Instagram CDN URLs are not persisted.** `fetch` downloads the post image at once and keeps only the post URL as
   `ref`; a rerun without a token keeps the stored files.
