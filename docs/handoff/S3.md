Branch `ws/generation`. Items 18, 20, 21, 22, 24, 25 and the fixTheme share of 9. `npm test` green (29 tests).

## What landed

- `factory/archetypes/restaurant.json`: seven archetypes (`grill-house`, `modern-cafe`, `patisserie-bakery`, `pizza-fast-food`,
  `traditional-family`, `fine-dining`, `bar-night`), each with `label`, `copyBrief` (Albanian, replaces the vertical's single brief),
  `itemGroups`, `layout` defaults and `fontBias`. `default` is `modern-cafe`. Shape: `{ vertical, default, archetypes: { id: {...} } }`
  so the Portal can build its select from `Object.entries(archetypes)` with `label`.
- `factory/lib/archetypes.mjs`: `loadArchetypes(vertical)`, `resolveArchetype(id, vertical)` (default with `fallbackReason` when the id
  is empty or unknown). Parked verticals without a file get one archetype built from their preset.
- `factory/lib/classify.mjs`: `classifyArchetype(place, photosSummary)` → `{ archetype, confidence, reason }` (claude-sonnet-4-6,
  JSON schema with the ids as enum). `summarizePhotos(photos.json)` strips the pool to scores and captions.
- `factory/lib/claude.mjs`: `askJson({ prompt, images, schema })`, the one structured call through the Claude Code login that copy,
  theme and classification share. S2 and S4 may want to import it instead of copying the `query()` boilerplate.
- `factory/lib/place-photos.mjs`: `resolvePhotos({ slug, place, photos, intake })` → `{ hero, gallery, previews, from }` in the config
  photo shape `{ src, source, author? }`. Cascade per slot: intake → photos.json picks (uncurated pool: first landscape Google photo
  and the next four) → place.json through `photoUrl` → nothing. **`photoUrl` is a copy of S1's contract** (`factory/lib/place.mjs`);
  once S1 merges, delete the copy and import from `place.mjs`.
- `factory/theme.mjs`: prompt takes the archetype (label, fontBias, its layout as the starting point), the curated photos (local
  files or URLs, up to 6, thumbs when the pool has them), `state.feedback` and `notes.md`. Returns `layout { hero, menu, gallery,
  rhythm, order }`. `fixTheme(input, { hasPhotos, layoutDefaults })` validates the enums, fills defaults (a missing key is the default,
  not a repair), forces `hero: "type"` and `gallery: "none"` when there are no photos. `FALLBACK_THEME` gained `layout` and its accent
  moved `#C8552D → #B84E29` because the old value failed fixTheme's own 4.5:1 surface rule (the same accent sits in
  `template/src/verticals/restaurant.json`; S6 may want to update it, the factory no longer reads that theme).
- `factory/demo.mjs`: `generateDemo(slug, { intake, only, feedback, archetype, log })` reads the Place folder and returns the config
  (writing is the job's business). Copy prompt gets Instagram captions, review texts, the archetype brief, feedback and notes;
  items carry `source: "evidence" | "filler"`, `testimonials [{ name, text }]` come from the reviews (first name, `Klient` when the
  author is unknown, empty when there are no reviews). Photos are objects. Intake still overrides everything (`intake.items` are
  `evidence`). `--only theme` keeps the copy fields byte for byte; `--only copy` keeps `theme` byte for byte; photos are refreshed
  on every run (they are data, not generation).
- `factory/jobs/generate.mjs`: transitions any status that can reach `generating` (found, qa_failed, qa_passed, ready,
  intake_received, live), classifies unless `state.archetype` is set, writes config.json, enqueues `build` and `qa` (skips a type
  that is not registered, with a log line). Throws → `failed`. Params: `only`, `feedback` (also stored in `state.feedback`),
  `intake` (path), `archetype` (id), `chain: false` to skip build/qa.
- `factory/batch.mjs`: the `generate-all` job (`found`, `hasRealWebsite` false, not a fixture, `--limit`, `--dry-run`) and the CLI
  that waits for the queue to drain and exits 1 when any generate failed.
- `factory/jobs/index.mjs`: `generate` and `generate-all` registered.
- `package.json`: `npm run demo -- <slug> [--only theme|copy] [--feedback "..."] [--intake file.json] [--dry-run]` runs the generate
  job (`factory/jobs/run.mjs generate`); `npm run theme -- <slug> [--dry-run] [--feedback "..."]` is the same job with `--only theme`
  (theme.mjs has no CLI of its own any more: it imports demo.mjs and vice versa, and a top-level await in a cycle deadlocks node).
  `--dry-run` generates, logs the theme/copy and writes nothing, no status change. `npm run demo:batch -- [--limit N] [--dry-run]`
  is the generate-all CLI. The foreground runner keeps the process alive until the chained build (and qa) finish.
