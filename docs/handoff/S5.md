# S5 handoff: Portal

Branch `ws/portal`. Everything lives under `portal/`; the only shared edit is the `portal` line in `package.json`.
`npm run portal` starts it on `http://0.0.0.0:4400` (`PORT`, `HOST` override) and sets `AUTO_COMMIT=1` unless
`AUTO_COMMIT=0` is in the environment. Nothing under `factory/` was changed and no job was added to the registry.

## Files

- `portal/server.mjs` routes, static files, the SSE stream, Demo view serving.
- `portal/router.mjs` route matching, urlencoded bodies, flash cookie, response helpers.
- `portal/actions.mjs` every POST: job enqueues by name, transitions, field saves, notes.
- `portal/data.mjs` reads: a Place with everything the pages show, archetypes, job lookups.
- `portal/pages/*.mjs` board, place, demo, search, jobs, due, clients, layout. `portal/html.mjs` escaping and dates.
- `portal/public/portal.css`, `portal/public/portal.js` (SSE log tail, confirm dialogs, `/` and `g b|j|s|d|c` keys).

## Job names and params the Portal enqueues

Checked against `registeredTypes()` at request time. An unknown type flashes "job `<type>` is not registered yet"
and enqueues nothing, so the buttons are safe before the streams merge (they render as "… (not registered)").

| Action (POST `/places/:slug/actions/<action>`) | Job | `params` |
| --- | --- | --- |
| `regenerate-theme` | `generate` | `{ only: 'theme', feedback? }` |
| `regenerate-copy` | `generate` | `{ only: 'copy', feedback? }` |
| `regenerate` | `generate` | `{ feedback? }` |
| `photos` | `photos` | `{}` |
| `qa` | `qa` | `{ vision: true|false, build?: true }` (`vision` false when the "no vision" box is ticked) |
| `build` | `build` | `{}` (with `back=demo` the redirect returns to the Demo view) |
| `deploy` | `deploy` | `{}` (the Foundation deploy job writes `state.pagesUrl` and moves `paid → live`) |
| POST `/search` | `lead-search` | `{ query, city, pages }`, no slug (record under the repo-root `jobs/`) |
| POST `/jobs` | any registered type | free `k=v` params, typed like `run.mjs` |

`feedback` is sent only when `state.feedback` is non-empty; S3's `generate` also reads `state.feedback` itself, so
either path works. `markPlaceFailed` is never set: `generate` and `qa` own their own failure transitions.

## Transitions the Portal performs

`approve` → `ready`, `reject` → `declined`, `retry` and `reopen` → `found`, and `status` with any `to` plus a
reason, all through `transition()`; a disallowed move is refused with the table's message as the flash.
The Fields form never changes status.

## Writes

- `POST /places/:slug/save` writes `state.contact`, `archetype`, `instagram` (`how: 'manual'` when the handle
  is new or changed; cleared with the handle), `followUp`, `priceAgreed`, `paidAt`, `domain`, `feedback` via
  `updateState`. When the phone changed and `config.json` exists, `business.phone` is updated too (and
  `business.whatsapp` filled from the digits when it was empty), committed as `config(<slug>): phone from the Portal`.
- `POST /places/:slug/notes` writes `notes.md`; `POST /places/:slug/note` appends to `state.notes` via `addNote`.

## For Integration

- **Phone**: `generate` (S3) rebuilds `config.json` from `place.json`, whose `phone` may be null. It should prefer
  `state.contact.phone` when set, otherwise the Portal's phone fix is lost on the next regeneration (backlog item 30).
- **Archetype**: the select reads `factory/archetypes/restaurant.json` (`{ vertical, default, archetypes: { id: { label } } }`)
  when present and falls back to a text input; the page shows `state.archetype || config.archetype` and the save
  writes `state.archetype` only, as S3 asked.
- **Demo view**: `/places/<slug>/demo/` is a wrapper (iframe + floating Rebuild); the build is served below it with
  no-store headers and root-absolute `href`/`src`/`srcset`/`url(` rewritten to the demo prefix. When S2's local photo
  store lands and `build` copies `photos/` into the build, relative URLs resolve with no change here.
- **Jobs page**: the running job and the queue come from `current()` and `queued()` in memory; finished records from
  `list()` on disk. The SSE stream at `/jobs/:id/events` replays the log file and then forwards `log` and `change`.
- No test file was added under `portal/`; `npm test` only covers `factory/`.
