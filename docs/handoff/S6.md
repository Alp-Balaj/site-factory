## What the Skeleton now reads from config.json

- `theme.layout { hero, menu, gallery, rhythm, order }`, defaults `photo / list / grid / tight / menu-first`. Unknown or
  missing values fall back one key at a time (`readLayout` in `template/src/lib/config.ts`), so a hand-edited config
  never breaks the build. `split` with no hero photo renders as `type`.
- `hero.image` and `gallery[]` entries: a string (old configs) or `{ src, source, author }`. `photoOf()` normalises;
  a string is rendered and never attributed. Google photos get "Foto nga <author>" (linked when `author.uri`) and
  "Powered by Google" in a `figcaption.credit` under the patch; Instagram and owner photos get nothing.
- `items[].source === 'filler'` gets the `labels.sample` tag ("shembull") next to the name in all three menu shapes.
- `itemGroups` (per archetype, written by S3) wins over the vertical's list; leftovers still go under `labels.otherGroup`.
- `testimonials [{ name, text }]` renders `Testimonials.astro` under `labels.testimonials` ("Çka thonë"), after About;
  nothing when empty.
- Labels added to `verticals/restaurant.json`: `sample`, `testimonials`, `photoBy`. `poweredBy` lives only in the
  defaults in `config.ts` (Google's own wording, not translated). The other three verticals inherit the defaults.
- Fallback accent in `verticals/restaurant.json` moved `#C8552D → #B84E29` as S3 asked (passes the 4.5:1 surface rule).
